# Results-matrix web app

React + TypeScript + Vite port of `app/app.py` (the Dash results-matrix viewer), built as static
files so it can be hosted on GitHub Pages. `app/app.py` still exists and works as a live Python app;
this is an additive, separately-deployed alternative — see `research_plan.md` / the repo root
`README.md` for project context.

## Development

```
npm install
npm run dev
```

## Data

Static JSON under `public/data/` is what the app reads at runtime — there is no backend, and
nothing here is hand-edited. It's generated by `scripts/export_web_data.py` at the repo root,
which imports `app/data.py` / `app/snapshot.py` directly so the two apps share one source of
truth for the numbers:

- `scores.json`, `methods.json`, `cases.json` — from the committed `docs/results/scores.parquet`
  and case.toml metadata, always regeneratable from a fresh clone.
- `snapshots/<case_id>.json` — from `results/pilot_snapshots.parquet`, which is gitignored and
  only produced by actually running a rolling pilot (`uv run python scripts/run_pilot.py`); the
  export step skips this with a warning if that file isn't present.

Regenerate after a pilot run:

```
uv sync --extra app
uv run python scripts/export_web_data.py --out web/public/data
```

Review the JSON diff before committing — unlike the source parquet, it's git-diffable.

## Deployment

Built via GitHub Actions (`.github/workflows/pages.yml`) into GitHub Pages, at the repo's root
Pages URL — the same workflow also builds the existing marimo EDA site into `/eda/`, since
`actions/deploy-pages` only publishes one site per repo. `vite.config.ts`'s `base` is set to the
repo's Pages path — see that file's comment before changing it.
